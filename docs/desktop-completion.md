后续更新：对话列表见 [侧栏对照](sidebar-alignment.md)，桌面占用处理已按用户要求升级为默认接管、执行后清理并重开，见 [桌面交接记录](desktop-handoff.md)。下文保留首次补全时的实现记录。

## 中断时发现的问题

GUI 文件已有初稿，但启动器只 sleep 后报告成功；队列、设置保存、任务添加和完成处理均为占位。部分模块导入的单例名称不存在；恢复函数把 prompt 误传为 cwd。会话页面使用了与扫描器不同的字段名，主窗口未连接核心操作，也未停止 QThread。模型选项包含与本机 Codex 无关的硬编码示例，旧统计把历史最高百分比当作当前用量。

## 核实依据

- 本机 `codex exec --help` 和 `codex exec resume --help` 实际支持指定模型、会话、JSON 输出和 stdin 提示词。已有对话使用明确 ID，不使用 `--last` 猜测目标。
- 只读检查本机 `state_5.sqlite` 的字段，以及实际 `token_count` 样本和模型缓存。缓存含多个限额分组；缺失值不能当作 0%。
- [官方非交互运行文档](https://learn.chatgpt.com/docs/non-interactive-mode)：核对 exec/resume、JSON 完成事件和默认只读权限。
- [Codex 官方协议源码](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)：核对 `TokenCountEvent` 的可空限额、`RateLimitSnapshot` 的主/次窗口和 `TurnCompleteEvent` 的可选错误。

没有把 `codex queue` 当作稳定依赖，没有写入官方 SQLite，也没有引入周期性 account/rateLimits/read 请求。

## 验证范围

自动测试覆盖：增量/半行/空限额日志、可选数据库字段、只读读取、最新百分比、窗口与周额度、缓冲、错过预约、崩溃重启、重复触发、保存失败、锁冲突、子进程输入/退出/超时，以及 GUI 设置与执行器连接。

五个页面已用合成数据渲染检查。真实本地扫描最近 100 个对话首次约 1.4 秒，缓存扫描约 0.02 秒（本机观察，非性能承诺）。

最终结果：38 项 pytest 测试全部通过，编译检查与 Ruff 致命错误检查通过。Windows 文件夹包及约 47.7 MB ZIP 已生成；打包后的 EXE 在 Qt offscreen 启动/退出检查中返回 0。Wheel 本地离线安装成功，命令入口返回版本 2.0.0。

没有发送真实 Codex 消息测试，因此登录状态、具体模型权限、服务器窗口起点和实际恢复响应仍需用户首次正常使用验证。Windows 包在本机构建；其他平台由 CI 验证，未声称完成跨平台人工验收。

## 可继续优化（本次不假装已实现）

1. Windows 登录时自启，以及明确的“唤醒电脑执行”系统任务选项。当前要求应用运行且电脑唤醒。
2. 在能够可靠区分账号身份后增加多账号限额归属，避免把切换账号前的本地快照用于新账号。
3. 对明确无副作用的启动消息提供可选有限次数重试；实际任务继续要求查看日志后手动重试，避免网络失败时重复修改文件。
4. 更长期的限额历史曲线、任务耗时统计、用户可调的执行超时；当前仅显示近期本地记录。
5. 安装器、代码签名和自动更新。当前提供完整文件夹便携包，保留 `_internal` 目录即可运行。

保留已有 PySide6 实现，未额外引入 QFluentWidgets。语言切换需重启；原有 headless daemon 保留原行为，新调度功能通过 GUI 使用。
